What it is

A tool for running the money side of a home poker game.

The host tracks buy-ins, rebuys, and cashouts during a session and uses the running totals to settle up afterward. Players who have a session's link can watch that session in their browser, read-only. There are no player accounts, and the data lives in the host's own database.

For players

You were sent a link. Here is what you can do with it.

A session link looks like https://your-app.vercel.app/s/<token>. Open it in any browser. No login, no install.

Two tabs

  • Session The game you were linked to: each player's buy-in, cashout, and net. Updates every few seconds while the game is live, and stays viewable with final standings after it ends.
  • Home Series stats across all of the host's games: sessions played this year, typical buy-in, longest session, biggest win and loss. These are aggregate numbers only.
You only ever see the one session you were linked to. The link does not let you browse other games, and there is no player-by-player history.

For hosts

The admin panel is where you run the session.

Go to /admin and enter your PIN. From there:

ActionWhat it does
New SessionStarts a game. Each session gets its own share link automatically.
Add PlayerAdds someone to the table with their first buy-in. Names autocomplete from past games.
RebuyAdds another buy-in to a player already at the table.
Cash OutRecords what a player leaves with. Their net is buy-ins minus cashout. Use the undo arrow to correct a mistake.
End SessionCloses the game and shows the final summary. You can reopen it if needed.
Copy LinkCopies that session's share link to send to the group.
ShareGenerates a screenshot summary card ranked by net, to post in a group chat.
Backup DataDownloads all sessions as a JSON file.
When the table balances (total cashouts equal total buy-ins), the summary shows a check instead of a number. If it does not balance, the difference is shown so you can find the missing count.

Sharing & privacy

Links are per-session and unguessable.

  • Every session has a random UUID token. The link is the only way in; tokens cannot be guessed or listed.
  • The root URL with no token (/) shows only a prompt to use a shared link. There is no public list of games.
  • A link keeps working after a session ends, showing the final standings.
  • Anyone who has a link can view that session, so share links the same way you would share the numbers themselves.

Architecture

All database access runs through serverless functions. The browser holds no database credential.

Security

One table, no anonymous database access, every path gated server-side.

  • All data lives in a single poker_data table whose row-level-security policy denies all anonymous access.
  • No database credential ships in the browser bundle. Reads and writes go through serverless functions using the service key.
  • Admin routes require an x-admin-secret header, checked with a constant-time comparison.
  • The observer route returns only the one session matching a token plus aggregate stats. Sessions cannot be enumerated.
  • The admin PIN is SHA-256 hashed in the browser before being sent.

Self-hosting

Runs on the Vercel and Supabase free tiers.

Database

Create a Supabase project and run supabase/migrations/20260101000000_init.sql in the SQL Editor. Copy the Project URL and the service_role secret from Project Settings → API.

Deploy

Deploy the repo to Vercel and set four environment variables:

VariableValue
SUPABASE_URLSupabase Project URL
SUPABASE_SERVICE_KEYservice_role secret
ADMIN_PINYour admin password
ADMIN_API_SECRETopenssl rand -hex 32
